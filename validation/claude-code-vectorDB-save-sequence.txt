  ---
  2. 그 설정으로 실제 파이프라인이 도는 전체 과정 (표준 흐름)

  위 설정값 기준으로 raw data → Qdrant 저장까지는 이렇게 진행됩니다:

  1. Raw data 수집 — ROBOT.md, SKILLS.*.md, TROUBLESHOOTING.md, ROBOT_LIMITS.json 등 문서/지식 원문을 가져옴 (config 서버 DB 또는 파일에서).
  2. 로딩 & 정제(clean) — 마크다운/JSON을 파싱해 불필요한 마크업·중복·공백 제거, 메타데이터(문서 출처, 로봇 프로필 sim/former, 섹션 제목) 추출.
  3. 청킹(chunking) — 긴 문서를 검색 단위로 분할. 보통 섹션/문단 기준 + 토큰 수 제한(예: 500~1000 토큰, 약간의 overlap). RagTopK=2라 검색 시 상위 2개 청크만 쓰므로, 청크가 너무 잘게
  쪼개지지 않도록 하는 게 중요합니다.
  4. 임베딩 생성 — 각 청크를 Azure OpenAI text-embedding-3-small(LlmEmbeddingBaseUrl)로 보내 벡터로 변환. text-embedding-3-small은 1536차원입니다.
  5. Qdrant 컬렉션 준비 — http://10.159.172.74:6333에 robo_claw_sim_azure 컬렉션이 없으면 생성. 이때 size=1536, distance=Cosine(임베딩 모델 특성상 코사인이 표준)로 설정. ⚠️  이
  차원/거리 설정은 이 저장소 어디에도 선언돼 있지 않으므로 에이전트 쪽 코드에서 확인해야 합니다.
  6. Upsert(저장) — 청크마다 PointStruct { id, vector(1536), payload{ text, source, robot_profile, section, ... } }를 만들어 컬렉션에 upsert. payload에 원문 텍스트와 메타데이터를
  넣어야 검색 후 LLM 컨텍스트로 되돌려줄 수 있습니다.
  7. 검색(런타임) — 질의가 오면 같은 임베딩 모델로 질의를 벡터화 → Qdrant에서 top-K(RagTopK=2) 검색, RagScoreThreshold=0.7 미만 점수는 버림 → 남은 청크의 payload를 LLM 프롬프트에 주입.
