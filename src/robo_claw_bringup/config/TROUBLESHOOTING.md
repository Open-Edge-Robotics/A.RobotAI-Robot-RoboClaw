# RoboClaw 에이전트 장애 조치 가이드 (TROUBLESHOOTING.md)

이 가이드는 로봇 구동 중 발생하는 **예외 상황(장애)에 대한 대응 절차**만 다룹니다.
일반적인 스킬 선택·파라미터 규칙은 시스템 프롬프트의 `[도구 선택 전략]`·`[파라미터 규칙]`을, 구동 한계(관절 범위 등)는
`[로봇 구동 한계 스펙 (ROBOT_LIMITS)]`를 따르며, 여기서는 그 내용을 반복하지 않고 **장애 발생 시의 행동 절차**만 기술합니다.

## 로봇별 적용 범위
- **Stretch3**: 팔/그리퍼 보유 → 매니퓰레이션 장애 대응이 적용됩니다. 복구를 위한 이동 전에는 팔 안전 자세를 확인해야 합니다.
- **Former**: 팔이 없음 → 매니퓰레이션 장애 섹션은 **해당 없음**. 조작 관련 장애는 발생하지 않습니다.
- **Butler**: 팔 조작은 스크립트 기반 → 팔 관련 복구는 SKILLS.md의 스크립트 실행 규칙을 따릅니다.

## 1. 내비게이션 장애 (Navigation Failures)

### NAVIGATION_TIMEOUT / GOAL_ABORTED (목적지 도달 실패)
* **원인**: 동적 장애물(사람, 임시 설치물)이 경로를 가로막거나, 슬립으로 인한 측위 오차 누적.
* **조치 가이드라인**:
  1. 기동을 멈추고 제자리에 정지합니다.
  2. 주변 카메라가 있다면 Pan-Tilt로 장애물 유무를 스캔합니다.
  3. 동적 장애물이면 5~10초 대기 후 다시 내비게이션을 시도합니다.
  4. 재시도 후에도 도달이 불가능하면 **`self_localize`를 자동으로 실행하지 않고** 실패 원인을 사용자에게 보고합니다.
  5. 사용자가 명시적으로 복귀를 지시하거나, 안전 지대가 확실히 알려진 위치일 때만 그곳으로 이동합니다. (Stretch3는 이동 전 팔 안전 자세 확인)

> 시스템 프롬프트 규칙과 일치: 주행 실패 시 `self_localize` 자동 실행 금지, 실패 이유를 보고하고 사용자 결정을 기다립니다.

## 2. 매니퓰레이션 장애 (Manipulation Failures) — 팔이 있는 로봇(Stretch3 등)만

### PLANNING_FAILED (경로 계획 실패)
* **원인**: 목표 자세/좌표가 팔의 작업 공간(Workspace) 밖(Singularity)이거나 주변 장애물과의 충돌 가능성.
* **조치 가이드라인**:
  1. 목표 좌표가 `[로봇 구동 한계 스펙 (ROBOT_LIMITS)]`의 관절 제한·최대 가동 범위 내인지 먼저 대조합니다.
  2. 제한을 초과하면 즉시 "가동 범위 초과로 인한 실행 불가"를 알리고 동작을 거부합니다.
  3. 팔을 기본 준비 자세(Ready Pose) 또는 홈 자세(Home Pose)로 복귀시킨 뒤, 좌표를 조금 수정한 다른 각도로 재계획을 시도합니다.

## 3. 하드웨어 진단 에러 (Hardware Diagnostic Errors)

### BATTERY_LOW (배터리 부족)
* **원인**: 배터리 잔량이 안전 임계치(15% 이하)로 하락.
* **조치 가이드라인**:
  1. 현재 수행 중인 모든 비필수 작업(물건 운반, 정밀 감지 등)을 일시 중단/보류합니다.
  2. 팔이 있는 로봇이면 안전한 홈 자세로 접어 고정합니다.
  3. 도킹 스테이션 복귀 스킬을 호출해 충전을 시작합니다.

### LIDAR_DISCONNECTED / CAMERA_DISCONNECTED (센서 수신 불능)
* **원인**: USB 케이블 접촉 불량, 하드웨어 전원 공급 이상, 또는 노드 오동작.
* **조치 가이드라인**:
  1. 주행형 로봇이면 즉시 `emergency_stop`을 호출해 정지합니다.
  2. 센서 데이터가 복구되지 않으면 맹목적인 주행을 금지하고, 현재 진단 에러 코드를 포함해 관제/사용자에게 상세 리포트를 전송합니다.
